## P11の目的

**設計 §3.1 の Done 11項目を、実行して確かめられる形にすること。**

機能はP10までで揃っている。足りないのは**証拠**である。設計 §21.3 は受入シナリオを
E01〜E12 と定めているが、いま E2E にあるのは4ファイル8件で、番号の対応も崩れている。

**12シナリオが揃い、決定性（10/10 同一結果）が測れること**が到達点である。

> **なぜ10回回すのか**（設計 §3.2）
>
> 1回通っただけでは「たまたま通った」と区別できない。AI出力と人間入力の両方を fixture で
> 固定したうえで10回走らせ、**結果が完全に一致する**ことを見る。ここが崩れていると、
> 以降の改修で何が壊れたのかを切り分けられない。

## やること

### 1. E2E 12シナリオ（`tests/e2e/`）

| ID | 目的 | 期待 | いまの状態 |
| --- | --- | --- | --- |
| E01 | 基本完走 | judged、17slot完了、85点と65点 | ある（前半・後半で2ファイル） |
| E02 | 再読込 | 同じslot・同じcursor・保存済み履歴 | ある（番号の付け直しが要る） |
| E03 | 二重送信 | speech 1件、409またはbutton disable | **無い** |
| E04 | AI障害 | paused、Retryで同一cursorから復帰 | **無い**（integration にはある） |
| E05 | 禁止Evidence | 422、確定なし | **無い**（integration にはある） |

| E09 | 決定性 | 10/10完走、結果が完全一致 | **無い** |

- **integration に同じ検査があるものも、E2Eとして1件は置く。** §21.3 は画面からの受入である
- fixture の差し替えは `MOCK_AI_FIXTURE`（P8 で追加）で行う。E04・E06・E07 は
  そのための fixture を足す（`content/fixtures/mock-ai/`）
- E08 は `MAX_AI_RUNS_PER_MATCH=5` で起動する（設計 §21.3）

### 2. 人間入力の fixture（設計 §15.7）

> 10回同一結果を得るには、AI出力だけでなく人間入力も固定する必要がある。
> `content/fixtures/e2e-human-input.json` に構造化立論1件（論点2件）とCX回答3件を置き、
> Playwrightはこれを読み込んで入力する。

- **このファイルはまだ無い。** 設計の指定どおりに作る
- 形は Zod で検証する（`schemas/` 側）。壊れた fixture を黙って使わない
- E2E は入力値をコードに書かず、この fixture から読む

### 3. 時間切れをどう起こすか（設計 §6.4 / §11 / **判断が要る**）

E10（prep が自動進行しない）と E11（立論未提出で完走）は、時計に依存する。
設計 §6.4 は `CLOCK_MODE=realtime|manual` を定めているが、**時計をどこが持つのかを書いていない**。
また設計 §14.3 のエンドポイント表に `HUMAN_TIMEOUT` を起こす口が無い。

着手時に、次のどちらにするかを決めてから実装すること。**決めた方と理由を PR 本文に書く。**

- **A: 持ち時間の経過をサーバが判定する。** スロットに入った時刻を保存し、`advance` の中で
  「持ち時間を過ぎていれば `HUMAN_TIMEOUT`」と判断する。エンドポイントは増えない。
  ただし `matches` に開始時刻の列が増える（設計 §13 に無い）
- **B: 時間切れを起こす口を1つ足す。** `POST /api/matches/:id/timeout` のような、
  設計 §14.3 の表に無いエンドポイントを追加する。E2E からは呼べるが、設計との差分になる

どちらでも、**client が勝手に時間切れを宣言できてはならない**（CLAUDE.md 禁止事項）。
`CLOCK_MODE=manual` のときは自動発火しないこと（設計 §6.4 / E10）。

### 4. 決定性の測定（E09・設計 §3.2）

- 同じ fixture で10回走らせ、**結果が完全一致する**ことを見る
- 比較するもの: `argument_key` の採番、`speechText`、`cx_turns` の中身、
  判定の得点と根拠、`ai_runs` の件数
- 時刻・UUID は結果から除いて比較する（それらは毎回変わってよい）
- **10回ぶんの実行が CI の時間に収まること。** 収まらないなら E09 だけ別 job にしてよい
